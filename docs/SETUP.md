# التجهيز — خطوة بخطوة

## أولًا: على جهازك

```bash
# ١. أنشئ مستودعًا خاصًا على GitHub باسم carsell (لا تضف README من الموقع)

# ٢. في مجلد المشروع الذي حمّلته
git init
git branch -M main
git add .
git commit -m "chore: design references, handoff and build spec"
git remote add origin git@github.com:<حسابك>/carsell.git
git push -u origin main

# ٣. أنشئ فرع التجربة
git checkout -b staging
git push -u origin staging
git checkout main
```

## ثانيًا: افتح Claude Code

```bash
cd carsell
claude
```

أول رسالة تكتبها — انسخها كما هي:

```
اقرأ README.md و CLAUDE.md و docs/BUILD-WEB-ADMIN.md كاملًا.
لا تكتب أي كود بعد. لخّص لي في عشرة أسطر: المكدّس، والمراحل،
وترتيب المهام، والقواعد التي لا تُخالف.
```

إن جاء التلخيص صحيحًا، فالسياق مضبوط. ابدأ المهمة ١.

## ثالثًا: قالب كل مهمة

```
اقرأ docs/BUILD-WEB-ADMIN.md القسم <رقم> و CLAUDE.md.
مرجع التصميم: design/<الملف>.dc.html — الشاشة <المعرّف>. افتحها واقرأ ترميزها.

المهمة: <رقم واسم المهمة من docs/TASKS.md>

قيود إلزامية:
- استخدم مكوّنات src/components/ui/ الموجودة. إن نقص مكوّن، أضِفه هناك أولًا بكل حالاته، ثم استخدمه.
- ممنوع لون أو مسافة أو ظل مكتوب — التوكنات فقط.
- كل رقم بـ font-num، والعرض بالأرقام العربية-الهندية.
- الفصل بالخطوط لا بالظلال.
- ممنوع any، ممنوع مكتبة UI جاهزة، ممنوع بيانات ثابتة.
- منطق العمل في src/lib/domain/ لا في مسار الـAPI.

معيار القبول: <من الجدول>
عند الانتهاء: شغّل الاختبارات، اعرض لقطة الشاشة، واذكر أي انحراف عن التصميم وسببه.
لا تبدأ مهمة أخرى.
```

## بروتوكول التعاون

Claude Code سيطرح عليك أحيانًا كتلة بعنوان `━━━ سؤال للمصمّم ━━━`.

**ما تفعله:** انسخها كما هي وأرسلها إلى المصمّم، ثم انسخ جوابه إلى Claude Code. لن يتوقّف عن العمل أثناء انتظارك — سيطبّق اقتراحه مؤقتًا ويضع تعليق `// DESIGN-Q` في الكود، ويصحّح عند وصول الجواب.

كل سؤال وجوابه يُسجَّل في `docs/DESIGN-DECISIONS.md`.

**إن كثرت الأسئلة التافهة** (تسمية، بنية مجلد، شيء مكتوب في المواصفة) فذكّره: «راجع بروتوكول التعاون في CLAUDE.md — هذا ليس مما يُسأل عنه.»

## رابعًا: بعد كل مهمة

1. افتح الشاشة في المتصفح، وافتح `design/<الملف>.dc.html` بجانبها. قارن.
2. صحّح الانحراف فورًا — لا تؤجّله.
3. `git add . && git commit -m "task-<رقم>: <المعرّف> <وصف>"`
4. علّم المهمة في `docs/TASKS.md`.

## خامسًا: النشر على Coolify

راجع `BUILD-WEB-ADMIN.md` القسم ١٢. الترتيب في كل مرة:

```bash
git checkout staging && git merge main && git push    # ينشر تلقائيًا
# افحص staging.carsell.one بصريًا
git checkout main && git push                          # ينشر الإنتاج
```

**لا تدفع إلى `main` مباشرة ولو كان التغيير سطرًا.**
